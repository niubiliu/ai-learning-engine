# AI Content Generation Rules

This document defines the rules that must be followed when generating AI learning content.

---

# 1 Terminology Explanation

When new technical terms appear in the content, they should be briefly explained.

Terminology explanations should be:

* concise
* easy to understand
* free of unnecessary academic complexity

---

# 2 Source Citation

The following content should include references:

* concept definitions
* technical explanations
* system architecture descriptions
* real-world application examples

Preferred sources include:

* official documentation
* academic papers
* open-source project documentation
* reputable technical articles

---

# 3 Examples

Concept explanations should include simple examples that help readers understand the idea.

Examples should be:

* simple
* intuitive
* easy to follow

---

# 4 Real-world Examples

When presenting real-world examples, priority should be given to:

* widely used AI systems
* well-known AI products
* major open-source projects

Examples should reflect real implementations whenever possible.

---

# 5 Diagrams

When concepts involve system workflows or structural relationships, diagrams should be generated.

Possible diagram types include:

* system flow diagrams
* component structure diagrams
* data flow diagrams

---

# 6 Knowledge Graph Initialization

The knowledge graph should start with a global skeleton that contains the five primary AI domains:

Systems
LLM Capabilities
Applications
Model Principles
Math Foundations

This skeleton acts as the base structure of the AI knowledge graph.
This skeleton must remain stable and serve as the root structure
for all future concept additions.

---

# 7 Knowledge Graph Expansion

The knowledge graph should grow incrementally.

Each learning session should:

* add new nodes
* update relationships
* attach concepts under the appropriate domain

The graph should **expand over time rather than being regenerated from scratch**.

---

# 8 Knowledge Graph Relationships

When adding new nodes to the knowledge graph, the system should establish relationships including:

* parent nodes
* child nodes
* related nodes

The graph should avoid isolated nodes whenever possible.

---

# 9 Learning Content Size

Each learning session may include **one or multiple related concepts**.

The number of concepts should depend on:

* concept complexity
* conceptual relationships
* overall readability

The system should avoid generating content that is too short or excessively long.

---

# 10 Learning Progress Tracking

The system should maintain the current learning progress.

Progress information may include:

* current domain
* learned concepts
* next concepts to learn

This ensures the learning sequence remains consistent with the knowledge map.

---

# 11 Duplicate Avoidance

The system should avoid repeating explanations for concepts that have already been learned.

If a concept reappears in a related context, it may be referenced rather than fully explained again.

---

# 12 Concept Naming Consistency

Concept names should remain consistent across learning sessions and the knowledge graph.

Equivalent or synonymous terms should be unified under a single canonical concept name.
